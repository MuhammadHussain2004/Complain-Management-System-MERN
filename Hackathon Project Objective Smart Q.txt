Hackathon Project Objective
Smart Complaint Management System — MERN Stack
Objective

Design and develop a Smart Complaint Management System using the MERN Stack (MongoDB, Express.js, React.js, Node.js) for an educational institution.

The purpose of this project is to create a centralized platform where users can register, get their accounts approved, log in through a single login system, submit complaints, and track the progress of their complaints. Administrators should be able to manage users, approve accounts, manage complaints, and monitor the overall system.

The system must support role-based access, where the application identifies whether the logged-in account belongs to a User or an Admin and provides access according to that role.

User Requirements

A registered user should be able to:

Create an account.
Wait for administrator approval before accessing the system.
Log in using the common login page.
Submit a complaint.
View their submitted complaints.
Track complaint status.
Edit or delete a complaint where permitted.
Admin Requirements

An administrator should be able to:

Log in through the same login page.
View and manage registered users.
Approve or reject pending accounts.
Activate/deactivate user accounts.
Manage user roles.
View all complaints.
Review and update complaint status.
Search and filter complaints.
Monitor complaint statistics through an admin dashboard.
Complaint Workflow

The system should support a complete complaint lifecycle:

Submit Complaint → Pending → Admin Review → In Progress → Resolved / Rejected

Each complaint should contain appropriate information such as title, description, category, priority, status, user, and timestamps.

Authentication & Authorization

The application must implement:

User registration
Single login system
Secure password handling
Authentication
Role-based authorization
Protected user/admin routes
Account approval mechanism

A newly registered account must not automatically become an Admin. The system should have an initial authorized administrator who can manage other accounts and their roles.

Expected Outcome

The final application should demonstrate a complete real-world workflow:

Register → Admin Approval → Login → Role Detection → User/Admin Dashboard → Complaint Management → Status Tracking → Resolution

Students are expected to research and decide the appropriate database structure, API design, frontend architecture, authentication approach, validation, UI/UX, and implementation details themselves.

The focus of the hackathon is to demonstrate practical understanding of MERN development, CRUD operations, REST APIs, MongoDB, authentication, authorization, role-based access control, and real-world problem solving.
